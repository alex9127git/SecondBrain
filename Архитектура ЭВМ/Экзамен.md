## Методы адресации
Регистровый метод адресации:  
- В команде указывается номер регистра общего назначения, содержимое которого интерпретируется процессором как операнд  
  
Косвенно-регистровый метод адресации:  
- Содержимое указанного в команде регистра интерпретируется процессором как адрес операнда  
  
Автоинкрементный метод адресации:  
- Содержимое указанного в команде регистра интерпретируется процессором как адрес ячейки памяти, в которой находится операнд, и после выборки операнда содержимое регистра увеличивается на 1 или 2 таким образом, чтобы указывать на адрес следующей по порядку ячейки памяти  
  
Косвенно-автоинкрементный метод адресации:  
- Содержимое указанного в команде регистра интерпретируется процессором как адрес ячейки памяти, в которой находится адрес операнда, и после выборки операнда содержимое регистра (адрес адреса) увеличивается таким образом, чтобы указывать на адрес следующей по порядку ячейки  
  
Автодекрементный метод адресации:  
- При интерпретации команды содержимое указанного в команде регистра вначале уменьшается на 1 или 2, после чего уменьшенное содержимое регистра интерпретируется процессором как адрес ячейки памяти, в которой находится операнд  
  
Косвенно-автодекременный метод адресации:  
- При интерпретации команды содержимое указанного в команде регистра вначале уменьшается на 2, после чего уменьшенное содержимое регистра интерпретируется процессором как адрес ячейки памяти, в которой находится адрес операнда  
  
Косвенная адресация со смещением (индексный метод адресации):  
- В дополнительном слове команды указывается так называемое смещение (индексное слово). Исполнительный адрес операнда определяется как сумма содержимого указанного в команде регистра и смещения (индексного слова)  
  
Непосредственный метод адресации:  
- Автоинкрементный метод адресации через регистр счетчик команд  
- Операнд указывается непосредственно в команде, после кода операции. Процессор получает в этом случае адрес операнда непосредственно из своего регистра-счетчика команд  
  
Абсолютный метод адресации:  
- Косвенно-автоинкрементный метод адресации через регистр счетчик команд  
- Во втором слове команды, т.е. в следующей за кодом команды ячейке памяти, указывается адрес операнда  
  
Относительный метод адресации:  
- Индексный метод адресации через регистр счетчик команд  
- Во втором слове команды указывается относительный адрес операнда, т.е. величина смещения адреса операнда относительно адреса самой команды (текущего содержимого регистра-счетчика команд процессора).  
  
Косвенно-относительный метод адресации:  
- Косвенно-индексный метод адресации через регистр счетчик команд
## Память и её организация
Программа называется перемещаемой, если **при ее размещении в разных местах памяти не требуется вносить изменений в ее код**.

Какой метод адресации следует использовать в перемещаемой программе для адресации данных, расположенных в теле программы? **Непосредственный и относительный** методы адресации.

Какой метод адресации следует использовать в перемещаемой программе для адресации регистров внешних устройств? **Абсолютный** метод адресации.

Память, организованная в виде стека:
- Прочитать слово, находящееся на вершине стека, можно только один раз
- Информация об один раз прочитанных данных теряется
- Записанные данные могут быть последовательно прочитаны только в порядке, обратном порядку их записи. Данные, записанные первыми, читаются последними; данные, записанные последними, читаются первыми
- Для доступа к данным не надо указывать адрес ячейки памяти
- В каждый момент времени для чтения доступна только ячейка памяти, являющаяся вершиной стека
- Для записи числа в стек используется автодекрементный метод адресации
- Для чтения числа из стека используется автоинкрементный метод адресации

Память с произвольным доступом
- Для доступа к данным надо указать адрес ячейки памяти
- В каждый момент времени для чтения доступна любая ячейка памяти независимо от ее расположения
- Информация об один раз прочитанных данных не теряется

Регистр-указатель стека всегда содержит адрес вершины стека, она же последняя ячейка, куда производилась запись (последняя записанная ячейка стека).
## Управление ходом программы
Подпрограммой называется программный модуль, к которому можно обращаться из любого места программы любое число раз.

Вложенные подпрограммы — это подпрограммы, вызываемые из других программ.

Команда условного перехода:
- используется для изменения содержимого регистра-счетчика команд в случае выполнения заданного условия и для перехода на команду с указанным адресом в случае выполнения заданного условия

Команда входа в подпрограмму:
- содержимое регистра-счетчика команд процессора пересылается в стек и запоминается как адрес возврата
- задаваемый в команде адрес входа в подпрограмму помещается в регистр-счетчик команд
- нельзя использовать команду безусловного перехода

Команда возврата из подпрограммы:
- адрес возврата выталкивается из вершины стека и помещается в регистр-счетчик команд
- нельзя использовать команду безусловного перехода
- нельзя использовать команду возврата из прерывания
## Архитектуры компьютеров
RISC:
- небольшое число простых форматов команд
- небольшое число простых способов адресации
- увеличенное число регистров общего назначения
- сокращенный набор команд
- фон-неймановская архитектура

CISC:
- большое число сложных форматов команд
- расширенное число разнообразных способов адресации
- небольшое число регистров общего назначения
- расширенный набор команд
- фон-неймановская архитектура
## Внешние устройства
Регистр состояния устройства — регистр, находящийся в интерфейсе внешнего устройства, с помощью которого можно разрешить или запретить прерывание внешнему устройству и с помощью которого осуществляется проверка готовности внешнего устройства к приему или передаче данных.

Состоянием разряда (флага) готовности внешнего устройства в его регистре состояния управляет внешнее устройство.

Прием или передача данных осуществляется через регистр данных внешнего устройства.

Готовность внешнего устройства к обмену информацией можно определить программным путем с помощью проверки состояния соответствующего разряда в регистре состояния внешнего устройства.

Для программно-управляемого ввода/вывода по опросу флага готовности характерны:
- низкая эффективность использования процессора
- простота программирования
- простота аппаратной реализации
- осуществление по инициативе выполняемой процессором программы
- осуществление под управлением выполняемой процессором программы
- контроль программой за количеством переданных байтов

Для того, чтобы осуществить передачу одного байта данных внешнему устройству в режиме ввода-вывода по опросу флага готовности внешнего устройства, необходимо:
- проверить разряд готовности в регистре состояния внешнего устройства
- переслать байт в регистр данных внешнего устройства

Для ввода/вывода в режиме прерывания характерны:
- более высокая эффективность использования процессора
- более сложное программирование
- более сложная аппаратная реализация
- осуществление по инициативе внешнего устройства
- осуществление под управлением выполняемой процессором программы

При включении питания компьютера разряд разрешения/запрета прерывания для внешнего устройства в регистре состояния его интерфейса автоматически устанавливается в состояние **прерывание запрещено**. Установка высокого проритета для процессора также запрещает прерывание всем внешним устройствам.

Чтобы запретить прерывание конкретному устройству, достаточно всего лишь установить низкий приоритет для этого устройства.

Алгоритм работы ЭВМ при обработке прерывания:
1. Процессор получает от внешнего устройства сигнал требования прерывания
2. Процессор завершает выполнение текущей команды
3. Текущее содержимое регистра-счетчика команд процессора и текущее содержимое регистра состояния процессора помещаются в стек.
4. Процессор посылает внешним устройствам сигнал готовности к прерыванию.
5. После получения от процессора сигнала предоставления прерывания интерфейс внешнего устройства, затребовавшего прерывание, передает процессору адрес своего вектора прерывания. В нём содержится адрес программы, требуемой для обслуживания прерывания, и все необходимые данные.
6. Процессор, получив от интерфейса внешнего устройства адрес его вектора прерывания, выполняет следующие действия:
	- содержимое первой ячейки этого вектора, то есть адрес программы обслуживания данного внешнего устройства, пересылается в регистр-счетчик команд процессора; 
	- затем содержимое второй ячейки вектора прерывания пересылается в регистр состояния процессора
	- данная информация устанавливается программным путем
7. Процессор выполняет программу прерывания, пока не дойдёт до команды возврата из прерывания
8. Из стека выталкивается и записывается в регистр состояния процессора сохраненное слово состояния процессора
9. Из стека также выталкивается и записывается в регистр-счетчик команд процессора сохраненный адрес возврата
10. Процессор продолжает выполнять команды по адресу возврата

Использовать команду возврата из подпрограммы для возврата из прерывания нельзя, так как она не возвращает прежнее состояние процессора.

Принципиальные проблемы, которые должны решаться при реализации ввода/вывода в режиме прерывания:
- необходимо разрешать конфликтные ситуации, возникающие при одновременном требовании прерывания несколькими внешними устройствами  
- Работа основной (прерываемой) программы должна приостанавливаться без какого-либо ущерба для ее выполнения
- Необходим механизм, позволяющий программным путем запрещать или разрешать прерывания всем или некоторым внешним устройствам, когда это необходимо
- Нежелательна жесткая привязка программы обслуживания к определенному месту в памяти ЭВМ
- Нужен механизм, обеспечивающий переход процессора на выполнение программы обслуживания именно того устройства, которое затребовало прерывание
